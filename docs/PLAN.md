# ballastviewer — Roadmap

Rebuild of BALLASTVIEW per `docs/BALLASTVIEW-SPEC.md`. One step per Claude Code session; each step ends buildable and testable. Check off steps as they complete and add notes future steps need.

## Fixed decisions

- Libraries exceed **50,000 photos** — speed is the top priority.
- **No compatibility** with old `MyLibrary.json` files. Fresh schema, no migration, no magic UUIDs from spec §7.5.
- **Persistence:** GRDB 7 / SQLite (WAL) inside a `Name.ballastlib` document package. In-memory catalog on the MainActor is the hot-path authority; DB is write-through (single-row updates). Collection counts update incrementally: O(changed photos × collections), full recompute only on bulk changes.
- **Keywords by id:** one `keyword` table (parent_id tree, nullable group_id; group_id = NULL ⇒ ad-hoc/grey). `photo_keyword` join table. Rename = one UPDATE (fixes C4). Paths (`PEOPLE > ANNA`) are derived.
- **Thumbnails:** ImageIO downsampling into buckets (256/768/2048 long edge), decode unrotated (Q5), rotate in the view layer (cache never invalidated by rotation). NSCache (~300 MB) + disk cache in Caches (HEIC), bounded decode concurrency, cancellation.
- **Actions:** one `AppAction` enum + `ActionDispatcher` (@MainActor) shared by keyboard/menus/MIDI. Exhaustive switch (fixes C5). `ControlSurfaceState` broadcast prepares LED feedback long before MIDI lands.
- **Sandbox on**, security-scoped bookmarks at folder scope. USB entitlement added only in step 11.
- All spec §16.1/16.2 bugs (D1–D6, C1–C14) get fixed; §16.3 quirks (Q1–Q28) preserved unless a deviation below overrides.
